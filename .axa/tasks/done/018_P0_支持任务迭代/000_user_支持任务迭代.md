现在任务执行完都是直接标记为完成。但是这个跟用户的日常习惯是不一致的。一般来说，用户会去看一下完成的效果满不满足期望。不满足期望的话，他会再追加一些需求。这种情况下，我们应该让这个需求单支持追加迭代。
1. 把任务从markdown文件改成文件夹。用户的输入会去存保存为一个 Markdown 文件，然后 Agent 的总结也保存成 Markdown 文件（要求agent将改轮次的汇总信息写入markdown，axa core检测到汇总文件提交才能进入review状态），这些文件都放在任务文件夹中。这样执行任务的时候，后续执行任务的时候，后面的 Agent 就有办法获取到完整的会话记录，也就是完整的上下文。markdown文件格式未{seq}_{role}_{title}.md，seq为文件产生的先后序列，三位数，用来排序，role为用户还是agent，title为该片段的关键内容，例如这个任务初始化文件为000_user_支持任务迭代.md（你有更好的可以改）
2. 任务元信息使用json文件放在任务文件夹目录下。
3. 任务修改默认需要review。console任务界面的“验收需要人工 Review”选项修改为“无需review”，默认不勾选。
